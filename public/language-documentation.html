Startup Language Documentation

Specification and examples for the .startup DSL compiler playground.

1. Language Purpose

.startup is a compact educational DSL designed to make core compiler stages visible: lexing, parsing, semantic analysis, IR generation, and runtime execution.

2. Core Rules

  • Every statement ends with ? (parser can recover if omitted in some cases).
  • Blocks use [ and ], and conditions use ( and ).
  • Line comments start with // and continue to the end of line.
  • Strings use double quotes, for example Vibe name ::> "Nova"?.
  • Booleans are written as VESTED (true) and CLIFF (false).
  • Naming convention: variables in camelCase, classes in PascalCase.

5. Statements

Construct Syntax Description
Declaration Burn x ::> 10? Declares and initializes a variable.
Assignment x ::> x +++ 1? Updates an existing variable.
Conditional PIVOT (x >>> 5) [ ... ] Runs block when condition evaluates true.
Loop SPRINT (x <<< 10) [ ... ] Repeats block while condition remains true.
Output PITCH x? Prints expression value to runtime output.
Input ACQUIRE founderName? Reads runtime input value.
Class declaration CLASS Startup? Declares a class in runtime symbol space.
Instantiation Vibe app ::> NEW Startup? Creates an instance of a class.

6. Operators and Delimiters

Core operators

  • ::> assignment
  • +++ --- ****** /// arithmetic
  • >>> <<< ??? !!? comparison
  • AND OR NOT logical

Delimiters

  • [ ] block delimiters
  • ( ) expression grouping
  • ? statement terminator
  • // ... line comments

8. Example Program

CLASS Startup?

Burn runway ::> 6?
Equity urgent ::> runway <<< 9?
Vibe product ::> NEW Startup?

PIVOT (urgent ??? VESTED) [
  PITCH "Raise now"?
]

PITCH product?

9. Compiler Pipeline

  1. Tokenizer: emits token stream and panic recoveries.
  2. Parser: constructs AST with node spans and trace.
  3. Semantic analysis: performs type checks and symbol validation.
  4. IR generation: emits instruction-like representation.
  5. Execution: walks AST and records timeline snapshots.
Phrase-level parser recovery can auto-insert missing ? in recoverable contexts, while panic mode can skip invalid lexemes and continue compilation.
